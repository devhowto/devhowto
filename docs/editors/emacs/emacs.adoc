[source,shell]
----
#!/bin/bash -e

#
# Example usage:
#   curl http://example.net/mbox | with-temp-file mutt -f
#   curl http://example.net/     | with-temp-file browser
#   curl http://example.net/     | with-temp-file emacs
#

test $# -gt 0 ||
exit 1

f="`mktemp -t with-temp-file.XXXXXX`"

trap 'rm -f "$f"' EXIT

cat >"$f"

# less(1)-style tty grabber.
exec </dev/tty || true

# subshell to avoid "w-t-f unset f" not reaping
("$@" "$f")
----

== Line wrapping

In some modes, we don't want to hard-wrap lines at a certain length, but instead let the lines run as long the person writing the code wants them to be.
One such case is for https://asciidoctor.org/docs/asciidoc-recommended-practices/#one-sentence-per-line[AsciiDoc “ventilated prose” or “one sentence per line”] style.

For those cases, kbd:[M+x] kbd:[auto-fill-mode] kbd:[RET].

Also try enabling and disabling `visual-line-mode`, which changes the way lines are displayed.
When enabled, my experience has been that it makes lines with links/URLs format less pleasant and readable, so I mostly keep `visual-line-mode` disabled.

Also see:

* https://superuser.com/questions/592154/how-can-i-turn-off-emacss-auto-line-wrapping-for-the-current-session
